# Contributing to Stretchu

Stretchu is a macOS menu bar app that reminds you to take short guided breaks, with a Pokémon
companion that levels up. Native Swift 6, SwiftUI and AppKit, macOS 14 or later, SwiftPM, no
external dependency. Everything runs locally: the app makes no network request.

## Architecture

```
Sources/Stretchu/
  App/         AppModel (the one observable object), status bar item, resources, localization
  Engine/      PauseScheduler, idle and meeting detection, Wi-Fi mode, clocks, sprite animation
  Game/        XPRules, Progression, Cycle, Streak, GameState, PokemonLine, settings
  Data/        StateStore (state.json), exercise catalog
  UI/          Panels (break steps, wake-up, level up), Menu, Companion, Settings, Components
  Debug/       Debug mode (compiled only with -DSTRETCHU_DEBUG)
  Localization/ en.lproj (source) and fr.lproj Localizable.strings
```

All the logic is pure Swift, testable without a UI, with an injectable clock (`Clock`): the
scheduler, the progression, the streak, the cycles, the state migration. Views only render what
`AppModel` exposes.

### Key rules

- **Breaks.** After 25 minutes of activity: wake-up, a 30 s warm-up, a 30 s exercise. "Later"
  postpones by 5 minutes (twice at most). "Skip" loses the break. Idle for 5 minutes or a locked
  screen pauses the timer. A meeting (microphone or camera in use, read without any permission)
  holds every panel back until it ends.
- **XP.** A completed break gives 2,500 XP, times the streak multiplier. Total XP to reach level n is 100 × n² (level 100 is 1,000,000). All the numbers
  live in `Game/XPRules.swift`; `ProgressionCalibrationTests` simulates 10 breaks
  a workday and expects level 100 on the 8th day.
- **Active hours.** `ActiveSchedule` (default 8:30 to 18:00, Monday to Friday) gates the work timer in
  `PauseScheduler`; a break asked for outside them gives XP but leaves the streak alone.
- **Streak.** Multiplier = min(5, 1 + streak): +1 per completed break, ×5 from the fifth. Skipping resets it. At each workday change,
  a workday without any completed break resets it; Saturday and Sunday
  are ignored.
- **Cycles.** A cycle is one Pokémon from level 1 to level 100. The current cycle is the last of
  `Progression.cycles`; the others are the Hall of Fame. At level 100 the cycle ends and a new one
  starts. A cycle keeps its line, dates, shiny flag, chosen branch and the species reached.
  Pokédex completion counts the species reached at least once, over the downloaded lines.
- **Lines and shiny.** `Resources/lines.json` lists the Pokémon lines (Gen 1). Two evolutions:
  levels 33 and 66. One: level 50. None: the same species to level 100. Eevee branches at level 50.
  At each choice of Pokémon there is a 20 % chance of a shiny (injectable random source), only
  for a line whose species all have a shiny sprite.
- **Setup and choices.** `OnboardingModel` holds the draft of the setup and `OnboardingChoices`
  applies it to the state. Replaying it never changes the XP, streak or cycles, nor the Pokémon.
  Giving a cycle up removes it and starts a new one that has no shiny draw; the cycle after that
  draws normally.
- **Persistence.** `~/Library/Application Support/Stretchu/state.json`, written atomically. Older
  formats are migrated when read (`GameState.init(from:)`, `XPRules.migratedXP`); tests load every
  fixture of `Tests/Fixtures`.

### Where the data lives

| What | Where |
| --- | --- |
| Pokémon lines, evolution levels, names | `Resources/lines.json` (generated by `scripts/generate-lines.py`) |
| Pokémon sprites, credits, stones | `Resources/Sprites/`, git-ignored, downloaded by `scripts/fetch-sprites.sh` |
| Exercises | `Resources/Exercises/catalog.json` (English), `catalog.fr.json` (French), pictures beside them |
| Programs | `Resources/Programs/general.json` (shipped), format in `docs/PROGRAM.md`, user files in `~/Library/Application Support/Stretchu/programs/` |
| Interface texts | `Sources/Stretchu/Localization/<language>.lproj/Localizable.strings` |
| User state | `~/Library/Application Support/Stretchu/state.json` |

## Build and test

```bash
make install     # downloads the sprites if needed, builds, signs ad hoc, installs, launches
swift test       # pure logic and localization
make test        # the same, for the release build and for the build with the Debug code
```

`make install` needs Xcode selected (`xcode-select -p` must not point to CommandLineTools). Tests that read the downloaded sprites are
skipped when they are missing (`make sprites` downloads them).

### Debug builds and prepared states

Debug mode (a page in the menu, ⌥ click on the icon, a copy of the state in `state.debug.json`,
simulated time, triggers for every panel) only exists in builds compiled with
`-DSTRETCHU_DEBUG`. `make install` never includes it.

```bash
make debug                                   # development build, launched in Debug mode
make demo STATE=lv65-x5                      # loads Tests/Fixtures/lv65-x5.json, then launches
make demo STATE=eevee-lv49-almost LANGUAGE=en
```

Your real `state.json` is never touched by these commands. In a development build, a few
environment variables help to look at screens: `STRETCHU_SUPPORT_DIR=<folder>` uses another data
folder (a fresh one shows the first-launch setup), `STRETCHU_SETUP_STEP=0...5` opens the setup on a
step, `STRETCHU_LANGUAGE=fr|en` forces a language, and the Debug page has "Replay the setup".

## Conventions

- Code, comments, identifiers and tests are in English. A comment explains the rule, not where
  it is written down.
- Interface texts go through `Localizable.strings` (`tr("key")`): add the key to both
  `en.lproj` and `fr.lproj`; a test fails otherwise. French texts use "tu", one line per title
  or button.
- Test files are named after the feature they cover.
- Logic stays in pure types with an injectable clock; views stay thin.
